# 系统管理页面设计说明

## 目标与范围

依据《04-实施计划》第 6 节，在 `Admin.Web` 中新增用户、角色、菜单、字典四个系统管理页面。页面复用现有 `src/api` 接口、`PaginationTable`、`DictTag` 和全局 `v-permission` 指令，不新增依赖，不修改后端接口，也不抽象超出阶段 D 所需的通用 CRUD 框架。

## 统一约束

- 用户、角色、菜单、字典类型和字典数据列表均使用 `PaginationTable`。菜单列表通过 `tableProps` 向组件内部的 `el-table` 传递 `row-key`、`tree-props` 和默认展开配置，并关闭分页。
- 所有状态展示使用 `DictTag`，状态字典类型统一为 `sys_user_status`。
- 新增、编辑、删除、重置密码、分配角色和分配菜单等业务操作按钮分别使用阶段 A4 定义的权限码；搜索和重置查询条件不视为数据变更操作。
- 分页请求统一发送 `{ pageIndex, pageSize, ...filters }`，消费后端 `{ total, items }`。
- 删除前使用二次确认；请求成功后给出成功消息，关闭对应弹窗并刷新受影响的列表；请求失败由现有 HTTP 拦截器统一提示，页面保留可重试状态。
- 页面使用 Vue 3 Composition API 与 `script setup`，保持与现有 Element Plus 技术栈一致。

## 页面设计

### 用户管理

页面由搜索卡片、分页表格以及三个独立弹窗组成。搜索条件为用户名、昵称和状态；表格展示用户名、昵称、邮箱、手机、状态、创建时间及操作。

新增和编辑共用表单，字段对应 `UserInput`。新增时密码必填且长度为 6–64，编辑时密码不展示，密码变更只通过独立的重置密码弹窗完成。角色字段使用多选 `el-select`。角色选项通过 `getRolePage` 以每页 100 条循环读取，避免角色总数超过单页上限时遗漏。编辑时通过 `getUser(id)` 获取最新详情和 `roleIds`。

分配角色使用独立弹窗和独立提交逻辑，初始值来自详情接口的 `roleIds`，保存时调用 `assignUserRoles({ userId, roleIds })`。重置密码弹窗只提交 `{ id, password }`。状态列使用 `DictTag`，状态变更仍在编辑表单内完成。

### 角色管理

页面由角色名/状态搜索区、分页表格、角色编辑弹窗和分配菜单弹窗组成。表格展示角色名、权限标识、排序、状态、创建时间及操作。

新增和编辑表单对应 `RoleInput`。编辑时通过 `getRole(id)` 获取最新详情。分配菜单弹窗加载 `getMenuTree()` 并用带复选框的 `el-tree` 展示。回显时根据 `row.menuIds` 计算已授权叶节点并调用 `setCheckedKeys`，让父目录自然呈半选状态，避免直接勾选父节点后误选其全部子节点。

保存授权时必须合并 `menuTreeRef.getCheckedKeys()` 与 `menuTreeRef.getHalfCheckedKeys()`，去重后调用 `assignRoleMenus({ roleId, menuIds })`，从而保证目录、菜单和按钮权限链完整。

### 菜单管理

页面使用关闭分页的 `PaginationTable` 展示 `getMenuTree()` 返回的树，底层 `el-table` 配置 `row-key="id"`、子节点字段 `children` 并默认展开全部节点。列包括菜单名称、图标、类型、路由路径、组件、权限标识、排序、状态及操作。

新增和编辑共用 `MenuInput` 表单，父级通过 `el-tree-select` 选择，并提供根节点。编辑时过滤自身及其后代，防止选择非法父级。`menuType` 驱动动态校验规则：目录要求 `path`；菜单要求 `path` 与 `component`；按钮要求 `perms`。切换类型时清理不适用字段，避免提交残留值。按钮父级只允许选择菜单节点；目录和菜单不能选择按钮为父级。

删除交由后端校验子节点约束；页面在请求失败时保留列表，由现有拦截器展示“存在子菜单，不能删除”等业务消息。

### 字典管理

采用已确认的左右分栏布局，窄屏下自动堆叠。左侧管理字典类型，右侧管理当前选中类型下的数据。两个区域均包含独立搜索条件、分页状态、加载状态和 CRUD 弹窗，并使用 `PaginationTable`。

类型表格展示字典名称、字典类型、状态和创建时间。点击行后设置当前类型，将数据页重置为第一页并按 `dictType` 加载。类型新增、编辑和删除分别调用现有类型 API；删除当前类型成功后重新选择剩余列表首项。

数据表格展示标签、键值、排序、样式、默认标志、状态和操作。数据表单固定携带当前 `dictType`，对应 `DictDataInput` 全字段。未选择类型时禁用新增数据操作并展示引导空状态。类型和数据状态均使用 `DictTag`。

## 数据与并发处理

每个请求使用 `try/finally` 恢复 loading/submitting 状态。保存按钮在请求期间禁用，防止重复提交。分页尺寸变化由 `PaginationTable` 的 `change` 事件统一更新页码和每页数量。搜索重置会将当前页设为 1 后重新加载。

弹窗打开时先重置表单和校验状态；异步详情返回后再填充数据。树回显等待 DOM 更新后执行。关闭弹窗不取消已发出的请求，但通过提交锁避免并发写入。

## 测试与验收

- 先添加页面契约测试，验证四个目标文件、`PaginationTable`、`DictTag`、权限码、用户独立弹窗、角色全选/半选合并、菜单树配置和动态规则、字典双列表布局等关键约束；先观察测试因页面缺失而失败。
- 实现后运行页面契约测试、现有 `npm test`、`npm run lint` 与 `npm run build`。
- 逐项检查阶段 D：分页参数和返回值、四类 CRUD、角色和菜单回显、半选节点提交、菜单动态必填项、字典类型与数据联动，以及所有业务操作按钮权限。
- 最终仅按用户指定范围暂存 `src/views/system`，使用指定提交信息创建阶段 D 提交。
